# Live agent acceptance probes

Run only an explicitly authorized evaluation in a disposable fixture. Use the
real packaged builders and copy successful native spawn arguments unchanged.
Replace read-only sample Plan tasks before execution. No real projects, commits,
installation, external calls or publication. These probes test actual host
behavior; helper unit tests and comprehension checks prove different claims.

The visible test chat is manager. Prepare two ordered executable units with
independent checks. Retain exact child handles, units, complete results, model
pairs and decisive event order. Keep evidence short and distinguish controlled
fixture faults from product defects.

| Case | Required observation |
| --- | --- |
| Direct execution | Existing manager assigns the released unit; executor reads the complete assignment and chooses relevant Skills. Later Steps stay unreleased. |
| Review and correction | Fresh read-only reviewer catches a seeded observable defect. Fresh executor corrects it; due review passes before dependent work. One writer at a time. |
| Group boundary | First group finishes checks, review, corrections and Plan closure before a fresh executor receives the next group. Completed effects/checks are retained. |
| Decision | Child names a real missing choice to the manager; dependent work stops. Manager asks directly and processes the actual answer once. No unanswered question grants permission. |
| Stop/resume | User stop prevents dispatch; exact child is interrupted and quiescence confirmed before Plan pause. Explicit resume continues known unfinished work without a second writer or repeated accepted work. |
| Compaction | Same manager/child assignment continues from retained identities, Plan and completed effects; no successor or context threshold. Claim actual host-compaction coverage only if observed. |
| Failure or uncertainty | Confirmed failed child can get a fresh remaining-work assignment only after prior writer quiescence. Unknown spawn/result/writer prevents replacement. A timeout creates no outcome. |
| Progress/completion | Direct Working on appears for changed released positions. Actual obstacles are blocked; waiting for active work is working. Requested scope closes only after Acceptance, due review, Plan closure and writer quiescence. |

For complete-file delivery, establish native completion, verify supplied hash
and read the full result before acceptance. Capture required output before
display; no truncated input is accepted. There are no receipt, startup or
handoff-control probes. Capacity refusals use ordinary failed-spawn handling:
retain diagnostic, no automatic retry or replacement chat. Do not invent close
or archival tools, change models silently or generate artificial context use.
